# «Кухня тата» (kuxniatata.pp.ua) — дизайн

## Навіщо

Особистий кулінарний щоденник: сайт із рецептами, які автор сам приготував і спробував. Читачі переглядають рецепти, шукають потрібний і можуть залишити коментар. Автор додає рецепти через Git (Markdown-файли), без адмінки.

## Цілі

- Кожен рецепт має власну сторінку з фото, інгредієнтами, кроками й особистими нотатками.
- Рецепти сортуються за **категоріями** (одна на рецепт) і **тегами** (кілька на рецепт); для кожної категорії та тега є своя сторінка.
- Зручний і швидкий **пошук** (назва, інгредієнти, текст), результат миттєво, без сервера.
- **Коментарі** з входом через Google (Facebook додається пізніше, за потреби).
- Безкоштовний хостинг, автоматичний деплой при push, SEO-теги, RSS, sitemap.
- Інтерфейс українською.

## Не цілі

- Адмінка чи редагування в браузері.
- Акаунти, профілі, збережені рецепти, рейтинги від користувачів.
- Мультимовність.
- Вхід через Facebook у першій версії.

## Антицілі (що вважається провалом, навіть якщо технічно працює)

- Реклама й сторонні трекери (тому не Disqus).
- Складний процес додавання рецепта: новий рецепт = один `.md` файл + фото.
- Сайт, що ламається, коли недоступний сервіс коментарів: рецепти мають відкриватися завжди.

## Обмеження

- Статичний сайт (Astro, генерація HTML під час збірки), без власного сервера.
- Безкоштовні плани всіх сервісів.
- Домен kuxniatata.pp.ua підключається наприкінці.
- Каталог проєкту наразі порожній (лише `propos.txt`), `git init` потрібен на старті.

## Підходи (як розглядали)

**Фреймворк.** Astro обрано замість чистого HTML, Eleventy, Hugo, Next.js: найкраще для Markdown-контенту, колекцій, зображень, SEO й RSS (деталі в `propos.txt`). Svelte/React не використовуємо, бо інтерактивність обмежена пошуком і коментарями.

**Коментарі** (вибір автора — варіант 1):
1. **Supabase** (Auth + Postgres): вхід через Google/Facebook/GitHub вмикається налаштуваннями, доступ керується правилами в базі. Мінус: безкоштовний проєкт засинає після тижня без активності, вирішується щотижневим «пінгом».
2. Власний код на Cloudflare (Pages Functions + D1 + OAuth): більше коду й ризиків безпеки, але нічого не засинає.
3. Disqus / Hyvor Talk: реклама й трекінг або платно.

Також відкинуто Giscus (вимагає акаунт GitHub) і анонімні коментарі (спам, немає входу).

## Рішення

Прийняті автором:
- Коментарі на Supabase, вхід через Google першим.
- Сайт про рецепти, які автор спробував; потрібні категорії, теги, швидкий пошук, коментарі.

Мої рішення (автор може виправити):
- Чистий Astro без UI-фреймворків; пошук і коментарі — звичайний JavaScript.
- Content collection `recipes`. Поля: `title`, `description`, `image`, `category`, `tags[]`, `time` (хв), `servings`, `ingredients[]`, `cookedOn` (дата), `notes` (мої нотатки: що вийшло, що змінити). Кроки — тіло Markdown.
- Категорії — фіксований список у схемі (щоб одруківка не створювала нову категорію); теги вільні.
- Пошук: Pagefind (індекс будується при збірці, працює на клієнті).
- GitHub Actions: збірка/тести/деплой на GitHub Pages і щотижневий «пінг» Supabase.
- Коментарі: таблиця `comments` (id, recipe_slug, user_id, author_name, avatar_url, body, created_at, approved). Читання — всім, запис — лише залогіненим, видалення — автору коментаря й власнику сайту. Компонент завантажується на сторінці рецепта окремо; якщо Supabase недоступний, сторінка показує «Коментарі тимчасово недоступні», а рецепт відображається повністю.
- Модерація в першій версії: власник видаляє коментарі через Supabase-панель; попередня модерація (`approved`) — лише якщо знадобиться.
- Анти-спам: вхід обов'язковий, ліміт довжини коментаря, обмеження частоти (на рівні правил/функції бази).
- SEO: `title`, `description`, Open Graph, canonical, `Recipe` JSON-LD на сторінці рецепта; sitemap і RSS через офіційні інтеграції Astro.
- Дизайн: чистий, світлий, адаптивний (мобільний пріоритет), фото в центрі уваги.

## Структура сторінок

- `/` — свіжі рецепти, список категорій, пошук.
- `/recipes/<slug>/` — рецепт + коментарі.
- `/category/<slug>/`, `/tag/<slug>/` — списки.
- `/search/` — пошук (Pagefind UI).
- `/rss.xml`, `/sitemap.xml`, 404.

- Налаштування проєкту Supabase й Google OAuth (потрібні дії автора: створити проєкт і OAuth-клієнт; будівельник дає покрокову інструкцію).
- Перші 3 демонстраційні рецепти (з тестовими фото) для перевірки сайту.
- Політика конфіденційності потрібна при додаванні Facebook; для Google на старті достатньо короткої сторінки.
