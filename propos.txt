https://www.rwpod.com/ - на чому зроблений?

RWpod зроблений на Astro + Svelte. Це статичний сайт-генератор: вихідний код відкритий у репозиторії rwpod/rwpod.github.io, де прямо вказано, що сайт побудований на Astro, Svelte та кількох невеликих бібліотеках.
Як це працює

    Astro генерує статичні HTML-сторінки з компонентів і контенту.

    Svelte використовується для інтерактивних частин інтерфейсу.

    Сайт публікується через GitHub Pages: репозиторій називається rwpod.github.io, а адреса сайту — rwpod.com.

    У репозиторії є GitHub Actions, які збирають і деплоять сайт при push; у конфігурації видно Astro 7.3.1.

Що це означає для тебе
RWpod	Твій сайт «Кухня тата»
Astro + Svelte	Можна зробити так само
Підходить для блогу/подкасту з багатьма сторінками	Підходить і для рецептів
Потрібні Node.js, npm та збірка	Трохи складніший старт
Автоматичний деплой через GitHub Actions	Можна налаштувати так само

Для першої версії я все одно радив би чистий HTML + CSS + JS: це швидше зробити, легше зрозуміти і достатньо для 5–20 рецептів. Astro варто брати, коли захочеш:

    додавати рецепти у Markdown;

    мати окрему сторінку для кожного рецепта;

    автоматично генерувати RSS, sitemap і SEO-теги;

    використовувати компоненти та шаблони;

    мати зручну структуру для десятків чи сотень рецептів.

Мій варіант для тебе

Почни з чистого HTML + JS, а коли з’явиться 10+ рецептів — переходь на Astro. Він добре підходить для контентного сайту, як RWpod, але не змушує одразу розбиратися зі збіркою, npm і компонентами. Astro створює статичний сайт, тому його можна безкоштовно хостити на GitHub Pages або Cloudflare Pages.

Тобто: RWpod — не “просто HTML”, а сучасний статичний сайт на Astro із Svelte-компонентами. Для kuxniatata.pp.ua це гарний орієнтир, але стартувати можеш значно простіше.

є щось краще за Astro?

Для твого кейсу — ні, Astro майже напевно найкращий вибір. Він найкраще поєднує Markdown-рецепти, окремі сторінки, зображення, теги, пошук, SEO, компоненти та безкоштовний деплой на GitHub Pages.

Astro й Eleventy обидва працюють із Markdown і підходять для контентних сайтів, але Astro з коробки має зручніші content collections, обробку зображень і компонентну модель. Eleventy гнучкіший, але CSS, JavaScript та інші ресурси треба налаштовувати вручну.
Чому Astro виграє

Для «Кухні тата» тобі потрібні саме ті речі, які в Astro зроблені добре:

    Рецепти в Markdown — кожен рецепт окремий .md файл.

    Окрема сторінка рецепта — Astro генерує її автоматично з шаблону.

    Картинки — вбудовані <Image /> і <Picture />, оптимізація та обробка Markdown-зображень.

    Теги й категорії — зручно зберігати в frontmatter та фільтрувати.

    RSS і sitemap — офіційні рішення Astro.

    SEO — ти контролюєш title, description, Open Graph і canonical URL у layout.

    Пошук — можна зробити швидкий клієнтський пошук через JSON і Fuse.js; для статичних сайтів також підходить Pagefind.

    GitHub Pages — офіційно підтримується через GitHub Actions.

Коли обрати інше
Eleventy

Обирай Eleventy, якщо тобі подобається писати майже чистий HTML і ти хочеш максимально простий, легкий проєкт без компонентів. Він має collections, теги та Markdown, але для зображень, пошуку й збірки ресурсів доведеться більше робити руками.
Hugo

Обирай Hugo, якщо плануєш тисячі рецептів і хочеш надзвичайно швидку збірку. Але для перших десятків рецептів перевага в швидкості збірки практично нічого не дає, а шаблони Hugo зазвичай складніші для новачка.
Next.js

Обирай Next.js, якщо в майбутньому точно захочеш:

    реєстрацію та профілі користувачів;

    збереження рецептів у базі даних;

    коментарі з модеруванням;

    кошик покупок;

    складну адмінку.

Для сайту, де ти сам додаєш рецепти через Git, Next.js — це «гармата по горобцях»: більше коду, конфігурації та можливостей помилитися. Astro краще саме для контентного сайту.
Моя чітка рекомендація

Бери Astro.

Він не обов’язково “простіший за все”, але найкраще відповідає твоїм вимогам:

text
Markdown + фото + теги + швидкий пошук + окремі сторінки + SEO + RSS + безкоштовний хостинг

І головне: ти не “застрягнеш” у ньому. Якщо пізніше захочеш додати форму коментарів, пошук по інгредієнтах або навіть акаунти — Astro дозволить поступово додати React, Svelte або Vue-компоненти лише там, де вони справді потрібні.
